# 电子台账 - 使用说明

一个手机浏览器直接打开的网页应用,覆盖:基础设置 → 每日记录(消耗/生产/出货/入库,带拍照)→ 自动库存 → 自动成本 → 日报 → 后台总览图表。

数据存在你自己的 Supabase 项目里(免费额度足够小生意用),所有人打开同一个网址,数据实时互通 —— 不需要每个员工注册账号或加入什么组织。

## 一、创建你自己的 Supabase 项目(免费)

1. 打开 https://supabase.com ,自己注册/登录一个账号(这一步需要你自己完成)。
2. 点 "New project",随便起个名字,选一个离你近的区域(如 Singapore),设置一个数据库密码(记下来,以后一般用不到)。
3. 项目建好后,进入左侧 **SQL Editor**,新建一条查询,把本文件夹里的 [`schema.sql`](./schema.sql) 全部内容粘贴进去,点 Run。
   - 这一步会建好所有数据表,并且自动创建一个叫 `ledger-photos` 的公开图片存储桶。
   - 如果最后两条建存储桶权限的语句报错(提示权限不足),没关系,去左侧 **Storage → ledger-photos → Policies**,用图形界面新增两条策略:允许所有人 `select`(读)和 `insert`(写)。
4. 进入左侧 **Project Settings → API**,复制这两个值:
   - **Project URL**(形如 `https://xxxxxxxx.supabase.co`)
   - **anon public** key(一长串字符;不要用 `service_role` 那个,那个是后台密钥不能公开)

### 1.5 导入你的产品/原材料清单(可选,已帮你导过一次)

如果你已经有产品或原材料清单(比如从原有系统导出的报表),可以直接批量导入,不用一个个手动录入。这份项目已经帮你导入过:

- **产品库 49 款**([`seed_products.sql`](./seed_products.sql))—— 只有编号/名称/单位,单价和期初库存留空待你在「设置」页补。
- **原材料库 66 款**([`seed_materials.sql`](./seed_materials.sql))—— 从 `PURCHASE INV JULY.pdf` 的 33 张采购发票整理,带真实采购成本价,还带了克重换算(见下面「按克记录消耗」)。

以后如果要换一批新数据重新导入(比如新开一个 Supabase 项目),流程是:先跑 [`schema.sql`](./schema.sql) 建表,再跑这两份 seed 文件。

## 二、把配置填进项目

打开 [`config.js`](./config.js),把里面的两个占位符换成你刚才复制的值:

```js
window.LEDGER_CONFIG = {
  SUPABASE_URL: "https://xxxxxxxx.supabase.co",
  SUPABASE_ANON_KEY: "你的anon key",
  PHOTO_BUCKET: "ledger-photos",
  PINS: { boss: "1234", staff: "0000" }
};
```

`PINS` 里的两个密码请改成你自己想要的数字(见下面「员工 / 老板身份」)。保存即可,不需要改其他任何文件。

## 三、部署成一个手机能打开的网址

这是纯静态网页(`index.html` + `app.js` + `config.js`),不需要服务器,随便挑一个免费静态托管都行,几分钟能上线:

- **Netlify**(最简单):打开 https://app.netlify.com/drop ,把整个 `ledger-app` 文件夹拖进去,几秒钟给你一个 `https://xxx.netlify.app` 的网址。想固定网址、以后能改动重新部署,就注册一个免费 Netlify 账号。
- **Vercel**:注册账号后 `vercel` CLI 或直接在网站上传文件夹部署,同样几分钟出网址。
- **GitHub Pages**:如果你已经有 GitHub 账号,把这个文件夹传成一个仓库,在仓库设置里开启 Pages,选 `main` 分支根目录即可。
- **Cloudflare Pages**:同样支持直接拖文件夹部署,免费。

以上账号注册、拖拽上传这些操作需要你自己在浏览器里完成(涉及账号创建和外部服务上传,不是我这边能替你做的部分)。部署好之后,把网址发给员工,大家在手机浏览器打开,再"添加到主屏幕"就能像小程序一样用了(已经配置了 manifest,支持添加到主屏幕全屏打开)。

## 四、开始使用

1. 打开网址后先去 **设置** 页,把你的原材料(名称/单位/单价/预警线/期初库存)和产品(名称/单位/预警线/期初库存)都录入一遍。
2. 如果账上已经有库存,记得把"期初库存"填对,不然后面算出来的剩余库存会不准。
3. 员工端用 **记录** 页的六个表单:**做产品**(推荐,见下方说明)/ 原材料消耗 / 生产记录 / 出货记录 / 原材料入库(供应商发票采购到货,库存才不会一直往下减)/ **现金采购**(见下方说明)。
4. **库存**、**成本**、**日报**、**总览** 都是自动算出来的,不需要手动维护。
5. **日报** 页可以选任意一天,查看当天的消耗/生产/出货明细和当日成本;右上角两个导出按钮:
   - **导出 PDF**:弹出浏览器的打印对话框,里面是一份排版好的报告模板(抬头店名+日期、成本/生产/出货统计卡片、各类记录表格、库存快照,低于预警线标红)。在打印对话框里选"另存为 PDF"(手机上一般叫"存储为 PDF"/"打印为 PDF")就能存成 PDF 文件。抬头店名在 [`config.js`](./config.js) 的 `BUSINESS_NAME` 里改。
   - **导出 CSV**:直接下载一份表格文件,能用 Excel / Numbers / Google Sheets 打开,适合拿去对账或进一步处理数据。

## 「做产品」:员工不用翻几十个原材料

记录页第一个标签就是 **做产品**,专门给员工用,流程是:

1. **今天做什么产品** —— 选一个产品(就一个下拉,不用在几十个原材料里找)。
2. 系统自动列出这个产品的**用料清单**:
   - 有标准配方 → 按配方列出来,填了"做出多少"之后每一行还会显示**建议用量**(配方用量 × 份数),并自动填进输入框;
   - 没配方但以前用这个页面做过 → 列出**上次做这个产品用到的料**和上次的用量;
   - 都没有 → 用"+ 加别的原材料"自己加,加完存成配方,下次就自动带出来了。
3. **一边做一边填**:每行填实际用量,做完一样就点左边的 ✓ 打勾(打勾时如果还没填数量,会自动按建议用量算)。填的内容**每改一下就存在这台手机里**,关掉页面、手机锁屏、明天再打开都还在,不会白填。
4. 最后按 **提交**,一次写入:每一行的原材料消耗 + 一条生产记录。省掉一条条切换表单的功夫。

其他说明:

- 数量单位跟别处一样:按克追踪的原材料可以选 g / kg,其他的按自己的单位(BAG/CTN/PCS…)。现金采购品项也能加进来。
- **材料成本只有老板/经理看得到**,员工界面不显示任何价钱。
- 老板/经理在这个页面底部有 **存成标准配方** 按钮:把这次填的用量除以"做出多少",存成这个产品的每份用量。以后员工选这个产品就自动带出来。(在 **计算** 页也能存配方,两边存的是同一份。)
- 想改配方就重新填一次再存一次,会覆盖旧的。

> 这个功能要求数据库里有 `material_consumptions.product_id` 字段(记录"这批料是做哪个产品用的")。
> 如果还没跑过这条 SQL,页面照样能用,只是"上次做这个产品用了什么"的自动回带会关掉,
> 浏览器控制台会有一条 400 提示。补跑一次即可:
> ```sql
> alter table material_consumptions add column if not exists product_id uuid references products(id) on delete set null;
> create index if not exists idx_mc_product on material_consumptions(product_id);
> ```
> 跑完之后,**日报**(网页版、PDF、CSV)里的每条消耗记录还会显示它是做哪个产品用掉的。

## 现金采购(不走供应商发票)

有些采购是自己或员工直接掏现金买的(巴刹摊位、杂货店零买、清洁用品、包装耗材),没有正式供应商发票。这类用 **记录 → 现金采购** 这张表单记,操作方式跟"原材料入库"一样:**选品项 → 填数量 → 填单价**。

- 品项来自一份**独立的"现金采购品项"清单**([`seed_cash_items.sql`](./seed_cash_items.sql),从 CASH CLAIM 表整理的 55 款),**跟原材料库完全分开**,不会混在一起。
- 选了品项会**自动带出上次买的价钱**,当场可以改;提交后系统会把该品项的价格更新成这次的最新价,下次再选就是最新的。
- 清单里没有的东西,下拉最后有 **"+ 新品项"**,填名称+单位就能当场加进清单,不用先去设置页。
- 单价栏**员工也看得到、要填**(跟"原材料入库"故意隐藏单价不同),因为这就是员工自己垫付了多少钱,要填清楚才能报销。
- 建议拍收据照片,方便对账。日报页单独统计"当日现金采购总额",导出 PDF/CSV 也都包含。
- 这类记录**不会**影响原材料库存——它是一笔独立的报销/支出记录,不是库存记录。
- 品项清单可以在「**设置 → 现金采购品项**」里维护(改名、改单位、改价格、归档)。

**现金采购品项也能按克算**:跟原材料一样,现金品项也有「每单位=?克」这个字段。比如"SEONG KEE 白胡椒粉 500G"是按包(PKT)买的 RM30.99,填上 500 之后:**买**的时候还是填几包,但**记消耗和做配方**时就能直接填克数(50g = RM3.10)。55 款里已经填好了 26 款(品名里写了重量的);包装袋、手套、煤气、清洁剂这些按件算的就不填,保持按件。

**现金采购的品项也能记消耗、也能进配方**:买回来总是要用掉的,所以「记录 → 原材料消耗」和「计算」页的下拉里都分了两组——**原材料**(原材料库的 82 款)和**现金采购**(这份清单的 55 款),两组都能选。成本按该品项的最近价格算,一样计入当日成本和日报;但因为这类东西不做库存追踪,记消耗**不会**让库存变负数(库存页只统计原材料)。

## 用 Excel 批量修改(导出 → 改 → 导回)

设置页的三个子页(**原材料库 / 产品库 / 现金采购品项**)顶部都有「**导出 Excel**」和「**导入 Excel**」两个按钮,用来一次改一大批东西,不用一条条点编辑:

1. 点 **导出 Excel**,下载下来的文件用 Excel 打开(表头是中文的:编号、名称、采购单位、采购单价RM、每采购单位克数、预警线、期初库存、已归档)。
2. 在 Excel 里随便改,改完保存。
3. 回到同一个子页点 **导入 Excel**,选那个文件,会先弹一个确认框告诉你「更新 X 条,新增 Y 条」,确认后才写进去。

几个要注意的:

- **第一列 `id(勿改)` 不要动、不要删**。系统靠它认出这是哪一条要更新。
- **要新增品项**:直接在表格最下面加一行,`id` 那格**留空**,其他填好就行,导入时会当新品项加进去。
- **删除**:导入不会删任何东西——表格里少掉的行只是不动它。要停用某个品项,把「已归档」那格填上 **是**(或者在应用里点「归档」)。
- 名称或单位空着的行会被自动跳过,确认框里会告诉你跳过了第几行。
- 数字格式随便填(有没有小数点都行),空着当 0;「每采购单位克数」留空表示这款不按克追踪。

## 每月更新物品和价格

每个月把当月的 purchase invoice / purchase list(Excel 或 PDF 都行)发过来,更新流程是固定的:

1. **正式供应商采购**(采购明细那部分)→ 更新 **原材料库**:已有品项按当月**最近一次**采购价更新单价,当月新出现的品项自动加进原材料库。
2. **CASH CLAIM 那部分** → 更新 **现金采购品项清单**:同样是更新最新价 + 加入新品项。
3. 两边**各归各的,不互相混**。
4. 如果某个品项当月的采购单位跟系统里记的不一样(比如以前按 KG 买、这个月按 BOX 买),不会自动改——因为换算比例不确定,乱改会让库存和成本算错,会单独列出来问你。

历史更新留档:[`update_materials_aug2026.sql`](./update_materials_aug2026.sql)(2026 年 8 月那次改了什么)。

## 按克记录原材料消耗

很多原材料是整包/整箱采购(比如"1 BAG = 50KG 糖"),但员工做菜实际用的是几百克这种量,直接按"几包"记消耗算不准成本。所以「设置 → 原材料库」的表单里有一个 **"每采购单位=?克"**(`pack_qty_grams`)字段:

- 填了这个数(比如 P1 SUGAR 填 `50000`,因为 1 BAG = 50000g):
  - **消耗记录**的数量输入框会直接按【克】填,成本自动按"每克成本"算,不用换算。
  - **入库记录**的数量输入框还是按【采购单位】填(比如买了几 BAG),系统自动把它换算成克存进库存里,所以采购和消耗用的是同一套计量单位,库存加减不会错。
  - **库存页**会自动把克数换算成更好读的 kg 显示。
- 不填(留空):这款原材料还是按老办法,消耗和入库都按采购单位(BAG/CTN/PKT...)记,不做克重换算。

**填 g 还是 kg 都行**:克重类原材料在**消耗表单**和**成本计算页**里,数量框旁边都有 **g / kg 下拉**,选 kg 就直接填公斤数(比如 12.5),消耗表单底下还会提示"= 12500 g"。存进数据库的统一是克,成本照样算得准;成本计算页保存成标准配方时,存的也是换算后的克数。

已经导入的 66 款原材料里,大多数都从发票的包装规格(如 "10X1KG"、"4X5KG")自动算出了 `pack_qty_grams`;少数几款(蛋按 TRAY、饮料粉末等)包装里看不出重量,先没换算,见 [`seed_materials.sql`](./seed_materials.sql) 开头的注释列表。想让这几款也按克算,告诉我每包实际多少克就行。

## 员工 / 老板身份

打开网页第一次会要求输入密码(在 [`config.js`](./config.js) 的 `PINS` 里设置):

- **员工密码**:解锁后只能看到"记录"这一页(消耗/生产/出货/入库四个表单),看不到库存、成本、日报、总览、设置,入库表单里的"采购单价"栏也会隐藏。
- **老板密码**:解锁后能看到全部功能。

右上角有个"切换"按钮,点了会清掉本机记住的身份,重新要求输入密码——同一台手机/平板,老板和员工可以用不同密码切换查看范围。

**这只是界面层面的隐藏,不是真正的权限控制**:密码写在 `config.js` 这个前端文件里,任何打开浏览器开发者工具、或者直接拿着 anon key 调 Supabase API 的人,仍然能读到全部数据(包括成本价)。这个方案适合"防止员工在店里的手机/平板上随手点开成本页面",但防不住存心要看数据的人。如果以后需要真正的权限隔离(员工账号在数据库层面就读不到成本字段),需要接入 Supabase 自带的登录系统(Auth)+ 改写数据库权限规则,工作量明显更大,可以在这版验证好用之后再做。

- 产品的标准原材料消耗比例(`product_recipe` 表已经建好但界面还没做编辑入口),用来把成本精确分摊到每件产品上。
